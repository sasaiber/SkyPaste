# Задача: обработка медиа и файлов в буфере обмена (macOS)
Clipboard manager · оптимизация RAM / CPU / батарея · все типы файлов

## Главный принцип
**Thumb генерируется один раз при захвате → хранится на диске → всё остальное время читается только с диска.** Никогда не читать оригинальные файлы для отображения в списке истории — только thumbs с диска. Оригинал читается только в момент вставки (paste). Пастборд после генерации thumb игнорируется.

## Ключевые метрики
* **Макс. thumbnail:** 200px (по длинной стороне)
* **JPEG качество:** 60% (~15–30 KB/thumb)
* **RAM на запись:** <50 MB (пик при захвате)
* **Захват thumb:** <100ms (на 1 файл)

## 🔴 P1 — Критично

### Захват thumbnail в момент копирования, не при показе
Когда `NSPasteboard` изменился — немедленно сгенерировать thumbnail и сохранить на диск. Не читать из пастборда повторно, так как источник может закрыться в любой момент.
* Генерация в фоновом потоке (`DispatchQueue.global(qos: .utility)`)
* Сохранять в `~/Library/Application Support/AppName/thumbs/`
* Имя файла — SHA256 от содержимого или UUID записи
* После сохранения — записать путь в локальную БД (SQLite)

> **Правила:** не блокировать main thread; fallback: иконка типа если thumb не удался.

### Матрица типов файлов — что захватывать и как
* **Изображения** (`.jpg`, `.png`, `.gif`, `.webp`, `.heic`, `.svg`, `.bmp`, `.tiff`, `.raw`)
  → `NSImage` → resize → JPEG thumb
* **Видео** (`.mp4`, `.mov`, `.avi`, `.mkv`, `.m4v`, `.webm`)
  → `AVAssetImageGenerator` кадр на 1s → JPEG thumb
* **Документы** (`.pdf`, `.docx`, `.xlsx`, `.pptx`, `.pages`, `.numbers`)
  → `PDFKit` / `QLThumbnailGenerator` → первая страница
* **Всё остальное** (`.zip`, `.app`, `.dmg`, `.py`, `.js`, `.txt`)
  → системная иконка через `NSWorkspace.shared.icon(forFile:)`

> **Примечание:** Для неизвестных расширений — всегда `QLThumbnailGenerator` как универсальный fallback. Если и он не справился — иконка расширения.

### Лимит памяти при захвате больших пачек
При копировании N файлов — не обрабатывать все параллельно.
* Использовать `OperationQueue` с `maxConcurrentOperationCount = 3`
* Освобождать `autoreleasepool` после каждого файла
* Если N > 50 — показать прогресс-индикатор в UI (не блокировать интерфейс)
* Если N > 500 — генерировать thumbs только для первых 50, остальные — по запросу (lazy)

## 🟡 P2 — Важно

### UI: не показывать все превью сразу
Паттерн отображения в зависимости от количества файлов:
* **1 файл** — полноразмерный thumb (макс 300px)
* **2–9 файлов** — сетка 3×3, все thumbs видны
* **10–99 файлов** — сетка из первых 9 + бейдж «+N»
* **100+ файлов** — коллаж из первых 4 + крупный счётчик

При клике — открывать отдельный попап с виртуальным скроллом. Рендерить только видимые ячейки + буфер 2 строки выше/ниже.

### Очистка дискового кеша
* Лимит папки thumbs: настраиваемый, дефолт `500 MB`
* При превышении — удалять по LRU (последний использованный удаляется первым)
* При удалении записи из истории — сразу удалять файл thumb
* Показывать занятое место в настройках приложения

### Оптимизация батареи: не работать когда не нужно
* Поиск изменений (Polling) `NSPasteboard` — не чаще 1 раза в 500ms (дефолт macOS-менеджеров)
* Throttle: если изменений нет — увеличивать интервал до 2s (адаптивно)
* Использовать `NSWorkspace` notifications вместо polling где возможно
* Самое дорогое — `AVAssetImageGenerator` для видео и обработка RAW-фото. Эти операции нужно откладывать на 5–10 секунд при работе от батареи, и делать иконку-плейсхолдер пока thumb генерируется.

## 🟢 P3 — Желательно

### Анимация / GIF: показывать статичный первый кадр
Не воспроизводить GIF в списке истории. Только при hover или раскрытии записи. Статичный thumb = первый кадр, сохранённый как JPEG.

### Метаданные файлов — что хранить в БД
В SQLite для каждого элемента буфера хранить:
`uuid`, `type` (image/video/doc/other), `extensions[]`, `file_count`, `total_size_bytes`, `thumb_path`, `thumb_status` (ok/failed/pending), `source_app`, `created_at`, `last_used_at`.
